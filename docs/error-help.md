# Локальная помощь при ошибках

Flow сопоставляет сообщение ошибки и последние строки текущей операции с небольшим набором проверяемых правил. Это не ИИ, не поиск в интернете и не обещание автоматически определить любую причину.

## Как пользоваться

1. При ошибке команды или задачи нажмите «Разобраться» в связанном уведомлении либо «Помочь с ошибкой» в консоли/настройках.
2. Окно разделяет факт из сообщения, возможную причину и ручные проверки; показывает фрагмент, применимость, источник и дату проверки правила.
3. Если правило не найдено, Flow прямо сообщает, что причина не установлена.
4. По желанию проверьте и отредактируйте предпросмотр отчёта, затем скопируйте его. Отправка в поддержку не выполняется автоматически.

Кнопки консоли и настроек хранят доступ к последней ошибке до закрытия приложения. Не каждое сообщение интерфейса является ошибкой команды: валидация полей, отмена и успешные действия не создают новый разбор. Фоновые опросы состояния не должны затирать полезную ошибку. Если уведомление переформулировано вызывающим кодом, кнопка в нём может отсутствовать; используйте постоянную кнопку.

## Первая база правил

| Сигнатура | Объяснение | Основной источник |
| --- | --- | --- |
| CUDA OutOfMemory / torch.OutOfMemoryError | Нехватка памяти GPU; отдельно от RAM/pagefile | [PyTorch CUDA memory management](https://docs.pytorch.org/docs/stable/notes/cuda.html#memory-management) |
| Windows 1455 / ERROR_COMMITMENT_LIMIT | Системный commit, RAM и файл подкачки | [Microsoft codes 1300–1699](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1300-1699-) |
| ENOSPC / Windows 112 | Нехватка места на диске записи | [Microsoft codes 0–499](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-) |
| HTTP 401 в каталоге/загрузках | Авторизация Civitai | [Civitai API errors](https://developer.civitai.com/site/guide/errors) |
| HTTP 403 в каталоге/загрузках | Отказ в доступе; не доказательство неправильного ключа | Civitai API errors |
| HTTP 429 в каталоге/загрузках | Rate limit или лимит пагинации; без ответа сервера не различаются | Civitai API errors |
| Сетевой timeout установщика/каталога/загрузки | Сеть, сервер либо таймаут клиента; не доказательство отсутствия интернета | [reqwest 0.12 timeout](https://docs.rs/reqwest/0.12/reqwest/blocking/struct.ClientBuilder.html#method.timeout) |

Проверка источников: 2026-11-04. Советы по batch size и профилям WebUI — консервативные ручные проверки, а не цитаты документации PyTorch. Настройки A1111 нельзя автоматически переносить в Forge. Дата правила — дата проверки разработчиком, не дата проверки конкретного компьютера.

### Добавление правила

`src/diagnostics.ts` содержит типизированную базу. Для каждого правила обязательны точная сигнатура, область действия, факт, оговорённая возможная причина, безопасные шаги, HTTPS-источник, дата проверки и применимость. Нужны положительные и отрицательные тесты. Одного общего «код 1» недостаточно. Приоритет имеет явно распознанное текущее сообщение; иначе проверяются последние 80 строк той же операции. Старые операции и разные этапы не смешиваются.

Новый URL документации также должен быть явно разрешён в `open_diagnostic_source` (`src-tauri/src/lib.rs`). URL из произвольного лога не открывается. Документация открывается в браузере только по явному нажатию, обычные сетевые запросы браузера при этом неизбежны.

## Данные и безопасность

- Диагностика не запускает установку, ремонт, удаление, изменение настроек или команду из сообщения ошибки.
- Отчёт формируется в памяти, без сохранения на диск и без передачи на сервер. Отдельного telemetry/LLM API нет.
- История ограничена 120 строками на этап, строка — 1500 символами; отчёт — 60 000 символами. Снимок ошибки не меняется от следующих логов.
- Сбор окружения выполняется только при открытии окна: существующие read-only проверки Git/Python, NVIDIA GPU/драйвера, RAM, commit/pagefile, диска и локального WebUI. Копируются только нужные поля, без путей пакета и ключей. Это сведения на момент проверки, не точный снимок момента ошибки. Точные версии PyTorch/CUDA внутри venv пока не собираются.
- Ожидание каждой проверки ограничено 8 секундами для интерфейса. Это не прерывает уже выполняющийся нативный read-only вызов; недоступные результаты отмечаются в отчёте.
- По шаблонам скрываются Bearer/Basic, именованные ключи/пароли, параметры и авторизация URL, домашние каталоги, UNC-пути, email и строки prompt. Очистка повторяется перед копированием отредактированного текста.
- **Это не гарантия анонимности.** Имена моделей, нестандартные секреты/пути, произвольный текст логов могут остаться. Предпросмотр и ручная проверка обязательны перед передачей. Исходная консоль и другие части приложения этим механизмом не очищаются.

## Проверка изменений

- `pnpm run build` — TypeScript и production Vite build.
- `pnpm run test:diagnostics` — Node 24+, сигнатуры, отрицательные случаи, контекст/границы истории, редактирование секретов и источники. Шаг добавлен в Windows build workflow.
- `python -m unittest discover -s tests -v` — существующие регрессионные проверки проекта.
- В Chromium проверены известная и неизвестная ошибки, подсказка уведомления, журнал задач, копирование изменённого отчёта с повторной очисткой, открытие источника только по нажатию, отмена/успешное уведомление/пассивный опрос, таймаут окружения, Escape, тёмная/светлая тема, ширина 390 px и reduced motion. Использовался mock нативного API: это не Windows end-to-end тест.

Перед выпуском нужна проверка на Windows: реальная ошибка загрузки Civitai; ошибка запуска WebUI и получение task-событий; сбор окружения; буфер обмена; открытие разрешённых источников и отклонение произвольного URL. Нативная сборка Tauri/Rust и эти сценарии здесь не проверялись.

Изменение не включает отдельные PR с позиционированием toast и восстановлением размера окна. После их слияния проверьте общую сборку; возможный конфликт `index.html` нужно разрешить, сохранив новые кнопки/диалог и перемещение `#toast` из PR позиционирования.
